# Scalp Scanner — เครื่องมือช่วยคัดกรองหุ้นอเมริกา (Web App)

> ⚠️ **นี่คือเครื่องมือช่วยคัดกรองหุ้น ไม่ใช่คำแนะนำการลงทุน**
> คะแนนและ "Expected Move" คำนวณจากค่าสถิติย้อนหลัง ซึ่งไม่ได้บอกอนาคต
> การซื้อขายหุ้นระยะสั้นมีความเสี่ยงสูงที่จะสูญเสียเงินต้น ผู้ใช้รับความเสี่ยงเองทั้งหมด

ระบบสแกนหุ้นอเมริกาสำหรับ scalping / day trade แสดงผลผ่านหน้าเว็บ
มีระบบให้คะแนนโอกาสเคลื่อนไหว 6 ปัจจัย แจ้งเตือนเมื่อราคาแตะแนวต้าน และทดสอบย้อนหลังได้

## 1. เริ่มใช้งานเร็วที่สุด

### วิธีที่ง่ายที่สุด (Windows)

**ดับเบิลคลิก `run.bat`** — จบ ไม่ต้องพิมพ์คำสั่งอะไรเลย

ไฟล์นี้ทำทุกอย่างให้เอง:
1. ตรวจว่ามี Node.js
2. **ติดตั้งไลบรารีถ้ายังไม่ครบ** (ครั้งแรกใช้เวลา 1-2 นาที) — ถ้าติดตั้งพลาดจะล้าง `node_modules` แล้วลองใหม่ให้อัตโนมัติ 1 ครั้ง
3. **ตรวจและอัปเดตไฟล์ `.env` ให้พร้อมใช้** (`setup-env.js`)
   - ไม่มี `.env` → คัดลอกจาก `.env.example`
   - มี `.env` เดิมอยู่แล้ว → เพิ่มค่าใหม่ที่ขาด + แก้ค่าที่ต้องเปลี่ยน + ลบบรรทัดซ้ำ
   - **สำรองไฟล์เดิมเป็น `.env.backup-<เวลา>` ก่อนทุกครั้ง**
   - **ไม่แตะ API key / LINE token / ค่าที่คุณตั้งเอง**
4. เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`
5. เริ่ม server

จากนั้นในหน้าเว็บ:
1. พิมพ์ Ticker ที่ช่อง **รายการเฝ้าดู** เช่น `TSLA, NVDA, AMD` → กด **+ เพิ่ม**
2. กดปุ่ม **▶ Start Scanner**

> **scanner ไม่เริ่มทำงานเอง** — ต้องกด Start ในหน้าเว็บ
> เพราะ server แยกจาก scanner loop จึงเปิดเว็บทิ้งไว้ได้แม้ scanner หยุดอยู่

### ลองเล่นก่อนตอนตลาดปิด

ตลาดหุ้นอเมริกาเปิด 20:30–03:00 เวลาไทย (ช่วง DST) ถ้าอยากลองตอนกลางวันไทย:

```bash
npm run demo
```

โหมดนี้ใช้**ข้อมูลจำลอง** ไม่ต่ออินเทอร์เน็ต ไม่ต้องมี API key
เห็นหน้าเว็บ ปุ่ม เสียงเตือน และ breakdown คะแนนได้ครบ
หน้าเว็บจะขึ้นแบนเนอร์สีม่วงเตือนไว้ตลอดว่าเป็นข้อมูลจำลอง

## 2. ติดตั้งแบบละเอียด

### 2.1 ติดตั้ง Node.js

ต้องใช้ **Node.js เวอร์ชัน 20 ขึ้นไป**

1. ไปที่ https://nodejs.org
2. ดาวน์โหลดเวอร์ชัน **LTS** (ปุ่มซ้าย)
3. ติดตั้งแบบกด Next ไปเรื่อยๆ ได้เลย
4. เปิด Command Prompt แล้วพิมพ์ `node -v` → ต้องขึ้นเลขเวอร์ชัน เช่น `v20.11.0`

### 2.2 ติดตั้งไลบรารี

เปิด Command Prompt ในโฟลเดอร์โปรเจกต์ (พิมพ์ `cmd` ในช่อง address bar ของ File Explorer):

```bash
npm install
npm run setup
```

> ถ้าใช้ `run.bat` ไม่ต้องพิมพ์ 2 คำสั่งนี้ — มันทำให้เองแล้ว

ไลบรารีที่ต้องมี (ติดตั้งอัตโนมัติ):

| ไลบรารี | เวอร์ชัน | ใช้ทำอะไร |
|---|---|---|
| `express` | ^5.2.1 | web server |
| `socket.io` | ^4.8.3 | ส่งข้อมูล realtime ไปหน้าเว็บ |
| `yahoo-finance2` | **^3.15.4** | ดึงแท่งเทียน + screener |
| `dotenv` | ^16.4.5 | อ่านไฟล์ `.env` |

> **⚠️ สำคัญ: `yahoo-finance2` ถูกอัปเกรดจาก v2 → v3**
> v2 หมดอายุการสนับสนุน (EOL) แล้วในปี 2025
> breaking change ที่แก้ไปแล้วในโค้ดนี้:
> ```js
> // v2 (เดิม — ใช้ไม่ได้แล้ว)
> import yahooFinance from 'yahoo-finance2';
> yahooFinance.suppressNotices(['yahooSurvey']);
>
> // v3 (ใหม่ — default export เป็น class ต้อง new)
> import YahooFinance from 'yahoo-finance2';
> const yahooFinance = new YahooFinance({ suppressNotices: ['yahooSurvey'] });
> ```

### 2.3 คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `npm start` | เปิด web server ที่ `localhost:3000` ← **ใช้ตัวนี้เป็นหลัก** |
| `npm run demo` | เปิด server ในโหมดข้อมูลจำลอง (ลองเล่นตอนตลาดปิด) |
| `npm test` | รัน smoke test — ตรวจว่าทุกอย่างทำงานถูก (ไม่ต้องต่อเน็ต) |
| `npm run backtest` | รัน backtest ใน terminal |
| `npm run cli` | โหมด CLI แบบเดิม (แสดงผลใน terminal + ส่ง LINE) |
| `npm run setup` | ตรวจ/อัปเดตไฟล์ `.env` อย่างเดียว (`run.bat` เรียกให้อัตโนมัติแล้ว) |

### 2.4 ถ้าเคยใช้เวอร์ชัน CLI เดิมอยู่แล้ว

ไฟล์ `.env` เดิมของคุณ **ใช้ต่อได้เลย** — `setup-env.js` จะปรับให้อัตโนมัติ

สิ่งที่มันจะแก้ให้:

| ค่า | เดิม | ใหม่ | ทำไม |
|---|---|---|---|
| `ATR_STOP_MULT` | 1.5 | **1.0** | **สำคัญมาก** — 1.5 เป็นค่าแบบ day trade ทำให้ stop กว้าง ~1.5 ATR แต่ระยะถึงเป้ามีแค่ ~0.5 ATR → R:R ได้ 0.33 เสมอ ไม่มีทางผ่านเกณฑ์ 1:1.5 → **ไม่มีสัญญาณออกมาเลย** |
| `UNIVERSE_SIZE` | 60 | 30 | ลดจำนวนหุ้นจาก screener ประหยัดโควตา API (คงไว้ 60 ก็ได้) |

และเพิ่มค่าใหม่อีก 28 ตัว (ทุกตัวมี default ที่ใช้งานได้ทันที)

**`MIN_SCORE=70` เดิมของคุณยังทำงานเหมือนเดิม** — เวอร์ชันนี้แยกเป็น 2 ค่า:
- `SIGNAL_SCORE` = คะแนนที่ถือว่าเป็น "สัญญาณ" ← ความหมายเดิมของ `MIN_SCORE` (ถ้าไม่ตั้ง `SIGNAL_SCORE` ระบบจะอ่านจาก `MIN_SCORE` ให้)
- `HIDE_BELOW_SCORE` = ซ่อนแถวออกจากตารางเลย (default 0 = แสดงทุกตัว)

> ถ้าคุณแก้ `ATR_STOP_MULT` เป็นค่าอื่นเองไว้แล้ว ระบบจะ**ไม่ทับ** และจะบอกให้ทราบ

## 3. หน้าเว็บมีอะไร

### หน้าแรก `/` — แดชบอร์ด

| ส่วน | รายละเอียด |
|---|---|
| **แถบสถานะ** | กำลังรัน/หยุด · ตลาดเปิด-ปิด · session ปัจจุบัน · เวลานิวยอร์ก · นับถอยหลังรอบถัดไป · ภาวะตลาด |
| **ปุ่มควบคุม** | ▶ Start · ⏸ Stop · 🔄 Scan Now — เปลี่ยนสีและ disable ตามสถานะจริงจาก server |
| **การ์ดสรุป** | หุ้นที่สแกน · สัญญาณที่เจอ · ผ่านด่านคุณภาพ · แจ้งเตือนแล้ว · ข้อมูลไม่อัปเดต · ภาวะตลาด |
| **รายการเฝ้าดู** | เพิ่ม/ลบหุ้น · ช่องกรอกราคาเป้าหมายรายตัว · ปุ่ม reset การเตือน |
| **ตารางหุ้น** | Ticker · ราคา · %เปลี่ยน · Volume · RVOL · แนวต้าน · ราคาเป้าหมาย · ที่มาเป้า · R:R · Expected Move · ขนาดไม้ · คะแนน · สถานะ |
| **Log realtime** | แทนข้อความที่เคยขึ้นใน terminal · แยกสี info/warn/error/success |
| **สถานะแหล่งข้อมูล** | provider แต่ละตัวใช้ได้ไหม + โควตาคงเหลือรายนาที/รายวัน |

**กดที่แถวใดก็ได้** → กางออกมาเห็น:
- **breakdown คะแนนทุกปัจจัย** — ค่าดิบ → คะแนน 0-100 → น้ำหนัก → คะแนนที่ได้ → คำอธิบาย "ทำไม"
- **แผนความเสี่ยง** — entry / stop / ที่มาของ stop / แนวต้าน / เป้ากำไร / R:R สองแบบ / ขนาดไม้ / เงินที่เสี่ยง
- ตัวเลขเทคนิค — RSI, ATR, VWAP, spread, แหล่งข้อมูล, อายุข้อมูล
- หัวข้อข่าว (ถ้ามี API key)
- เหตุผลที่ตกด่าน (ถ้าตก) และข้อควรระวัง

### สีของแถวในตาราง

| สี | ความหมาย |
|---|---|
| 🟡 **เหลืองกระพริบ** | ราคาแตะเป้าหมายแล้ว |
| 🔴 **แดงจาง + ขอบซ้ายแดง** | ข้อมูลไม่อัปเดต — ตัวเลขในแถวนี้ใช้ไม่ได้ |
| ⚪ **จางลง** | ตกด่านคุณภาพ (ยังแสดงไว้ให้เห็นว่าตกเพราะอะไร ไม่ซ่อน) |

### หน้า `/settings`

ปรับได้ทุกอย่างโดยไม่ต้องแก้ไฟล์ — บันทึกลง `data/settings.json` และมีผลทันทีไม่ต้องรีสตาร์ท:

- session (`regular` / `pre` / `post` / `all`), timeframe, ช่วงเวลาสแกน
- เงินทุน, % ความเสี่ยง, R:R ขั้นต่ำ, ตัวคูณ ATR สำหรับ stop
- **น้ำหนักคะแนน 6 ปัจจัย** (slider + บังคับให้รวม 100%)
- การหาแนวต้าน (ระยะแจ้งเตือน, แท่งยืนยัน pivot, การรวมโซน)
- ด่านคุณภาพข้อมูล (spread, อายุข้อมูล, มูลค่าซื้อขายขั้นต่ำ)
- universe (เปิด/ปิด auto screener, ช่วงราคา, วอลุ่มขั้นต่ำ)
- **API keys ทั้ง 5 เจ้า** — กรอกผ่าน UI ได้ ไม่ต้องแก้ไฟล์
- เปิด/ปิดการส่ง LINE + ปุ่มส่งข้อความทดสอบ

> API key ที่บันทึกแล้วจะแสดงเป็น `••••1234` — ระบบไม่ส่งค่าเต็มกลับมาที่เบราว์เซอร์

  ระบบจึง**ไม่ใช้ Finnhub สำหรับแท่งเทียน** ใช้ Yahoo เป็นตัวหลักแทน
  Finnhub ยังใช้เป็นแหล่งราคา realtime, ปฏิทินงบ และข่าวได้ตามปกติ
- **Alpha Vantage เหลือ 25 ครั้ง/วัน** (เมื่อก่อน 500) — ระบบจึงเรียกเฉพาะหุ้น 3 ตัวที่คะแนนสูงสุดของแต่ละรอบ

  ใช้ได้ ~13 รอบ/วันเท่านั้น จึงเหมาะเป็นตัวสำรองอย่างเดียว
- **FMP float/short interest** อาจไม่อยู่ใน free tier แล้ว — ถ้าเจอ 403 ระบบจะจำไว้และไม่เรียกซ้ำ (ไม่เผาโควตา)

## 5. ระบบให้คะแนน 6 ปัจจัย

คะแนน 0-100 บอกว่าหุ้นตัวไหน **"มีโอกาสเคลื่อนไหวแรง"** ที่สุดในรอบนั้น
ทุกปัจจัยแปลงเป็น 0-100 ก่อน แล้วคูณน้ำหนัก → รวมเป็นคะแนนสุดท้าย

| ปัจจัย | น้ำหนัก | เหตุผล |
|---|---|---|
| Relative Volume (RVOL) | 25% | วอลุ่มเทียบค่าเฉลี่ยช่วงเวลาเดียวกัน — ตัวชี้วัดสำคัญที่สุดของ scalping |
| ATR% / ความผันผวน | 20% | หุ้นนิ่งเทรด scalp ไม่ได้ ต้องมีระยะให้วิ่ง |
| ระยะห่างจากแนวต้าน | 15% | ใกล้เบรกเอาท์ = โอกาสวิ่ง |
| Momentum | 15% | %เปลี่ยนแปลง + การเรียงตัวและความชันของ EMA |
| News Sentiment | 15% | ข่าวบวก + วอลุ่มมา = โอกาสสูง |
| Spread / สภาพคล่อง | 10% | spread กว้าง = ต้นทุนสูง หักคะแนน |

**ปรับน้ำหนักได้ในหน้า Settings** (slider · ระบบบังคับให้รวม 100%)

### จุดที่ต่างจากตารางข้างบน — และเหตุผล

**1. ATR% เป็น "ระฆัง" ไม่ใช่ยิ่งมากยิ่งดี**
หุ้นนิ่งเกินไป scalp ไม่คุ้มค่าธรรมเนียม แต่หุ้นเหวี่ยงเกินไปก็คุมความเสี่ยงไม่ได้
(stop กว้างมาก ขนาดไม้เล็กจนไม่คุ้ม และโดน stop จากสัญญาณรบกวนตลอด)
→ ช่วงที่ได้คะแนนเต็มคือ **1.5%-3.0% ต่อวัน** ปรับได้ในหน้า Settings

**2. ปัจจัยนี้ใช้ ATR% "เทียบเท่ารายวัน" ไม่ใช่ ATR% ของแท่ง 5 นาที**
ATR ของแท่ง 5 นาทีอยู่ราว 0.1-0.5% ของราคา ส่วน ATR รายวันอยู่ราว 1.5-5%
ถ้าเอา ATR ของแท่ง 5 นาทีมาเทียบกับช่วงที่เหมาะของรายวัน หุ้นทุกตัวจะได้ 0 คะแนนหมด
→ ระบบใช้ ATR(14) จากแท่ง **daily** ตรงๆ (cache 12 ชม.) ถ้าไม่มีจึงประมาณจาก intraday × √(แท่งต่อวัน)

**3. ระยะห่างจากแนวต้าน peak ที่ 0.3-1.5 ATR ไม่ใช่ "ยิ่งใกล้ยิ่งดี"**
ชิดแนวต้านเกินไป (< 0.15 ATR) หมายความว่าเป้ากับราคาแทบเท่ากัน → R:R หายไปแล้ว
→ และมีโบนัสตามจำนวนครั้งที่ราคามาชนโซนนั้น (ชน 3 ครั้ง = กำแพงจริง, wick เดี่ยว = อ่อน)

**4. ไม่มีข้อมูล sentiment ได้ 50 คะแนนกลางๆ พร้อมป้ายบอกว่าไม่มีข้อมูล**
ห้ามให้ดูเหมือนว่า "ตรวจแล้วไม่มีข่าวร้าย" เพราะจริงๆ คือ "ยังไม่ได้ตรวจ"
เมื่อมีปัจจัยที่คำนวณไม่ได้ ระบบจะแสดงว่าคะแนนมาจากน้ำหนักรวมเท่าไหร่ เช่น `(จากน้ำหนัก 90%)`

### ตัวเลขประกอบ

**Expected Move %** — ATR(14) รายวัน บอกว่าตามสถิติหุ้นตัวนี้มักแกว่งกี่ % ต่อวัน
เป็น **ค่าสถิติย้อนหลัง ไม่ใช่การพยากรณ์**

**Risk / Reward** — คำนวณจาก:
- entry = ราคาปัจจุบัน
- stop = ตัวที่แคบกว่าระหว่าง `ราคา − 1.0×ATR` และ `ใต้แนวรับ/swing low` (มีพื้นขั้นต่ำ 0.35×ATR)
- target = แนวต้าน + 0.5×ATR (การเล่นจริงคือแนวต้านแตกแล้วราคาวิ่งต่อ)
- **กรองสัญญาณที่ R:R ต่ำกว่า 1:1.5 ออก**

แสดง R:R สองแบบเพื่อความโปร่งใส: เป้าเลยแนวต้าน (หลัก) และออกที่แนวต้านพอดี (อนุรักษ์นิยม)

> **⚠️ หมายเหตุสำคัญเรื่อง `ATR_STOP_MULT`**
> ค่า default เปลี่ยนจาก **1.5 → 1.0** และสูตรเลือก stop เปลี่ยนจาก `Math.min` → `Math.max`
>
> เหตุผล: สูตรเดิมเลือก stop ที่ "กว้างกว่า" (ปลอดภัยจากสัญญาณรบกวน แต่เสีย R:R)
> ซึ่งเป็นการตั้งค่าแบบ day trade เมื่อระยะ stop ≈ 1.5 ATR แต่ระยะถึงเป้า ≈ 0.5 ATR
> R:R จะได้แค่ ~0.33 เสมอ **ไม่มีทางถึง 1:1.5 ที่สเปกกำหนด** → ไม่มีสัญญาณออกมาเลย
> เครื่องมือขัดขากันเอง
>
> ดูคำอธิบายเต็มในคอมเมนต์ของฟังก์ชัน `riskReward()` ใน `src/scoring.js`

**Position Size** — `(เงินทุน × %ความเสี่ยง ÷ ความเสี่ยงต่อหุ้น) × ตัวคูณตามภาวะตลาด`

### ภาวะตลาด (regime)

ประเมินจาก SPY + QQQ แล้วปรับความเข้มงวดอัตโนมัติ:

| ภาวะ | เกณฑ์คะแนน | ตัวคูณขนาดไม้ |
|---|---|---|
| RISK-ON | −5 | ×1.00 |
| NEUTRAL | 0 | ×0.75 |
| CAUTIOUS | +8 | ×0.50 |
| RISK-OFF | +15 | ×0.35 |
| ประเมินไม่ได้ | +8 | ×0.50 (ระมัดระวังไว้ก่อน) |

## 6. วิธีหาแนวต้านและราคาเป้าหมาย

### ราคาเป้าหมายแจ้งเตือน

| กรณี | ราคาเป้าหมาย | ป้ายในตาราง |
|---|---|---|
| กรอกเอง | ราคาที่กรอก | **ตั้งเอง** (ป้ายฟ้า) |
| ไม่กรอก | **แนวต้าน × 0.999** (แนวต้าน −0.1%) | **auto (แนวต้าน −0.1%)** |

คำนวณแนวต้านใหม่**ทุกรอบสแกน** และแสดงค่าล่าสุดในตาราง

### วิธีหาแนวต้าน: Fractal swing pivot + ATR clustering

**ทำไมไม่ใช้ `highest high ของ 20 แท่งล่าสุด` ตรงๆ:**
ถ้าหุ้นกำลังทำ new high อยู่ ค่านี้จะ ≈ ราคาปัจจุบัน
→ ราคาเป้าหมาย (แนวต้าน × 0.999) จะอยู่ **ต่ำกว่า** ราคาปัจจุบัน
→ ระบบจะแจ้งเตือนทันทีทุกรอบ ไร้ความหมาย

**ทำไมไม่ใช้ pivot point รายวัน (R1/R2 จาก H/L/C เมื่อวาน):**
คำนวณครั้งเดียวตอนเช้าแล้วนิ่งทั้งวัน หุ้น scalp ที่วิ่ง 8% จากข่าวจะทะลุ R2 ใน 20 นาทีแรก
แล้วอีก 6 ชั่วโมงที่เหลือไม่มีแนวอะไรให้ใช้เลย
→ pivot point เหมาะกับกรอบเวลาใหญ่ ไม่เหมาะกับ scalping บน 5 นาที

**วิธีที่เลือก:**

1. **Fractal pivot** — แท่งนับเป็น pivot high เมื่อ high สูงกว่า high ของ k แท่งทั้งซ้ายและขวา (k=2)
   ความหมาย: ราคาไปถึงจุดนั้นแล้ว **ถูกปฏิเสธจริง** มีคนขายรออยู่จริง
   ข้อดีสำคัญ: เพราะต้องรอ k แท่งขวายืนยัน มันจะ**ไม่มีทางเป็นแท่งปัจจุบัน** → ไม่เกิดปัญหาเป้าหมายอ้างอิงตัวเอง

2. **Clustering** — pivot ที่ราคาห่างกันไม่เกิน 0.25 × ATR ถือเป็น "โซนเดียวกัน"
   ใช้ **ขอบล่าง** ของโซนเป็นราคาที่ actionable (แรงขายเริ่มตรงนั้น)
   นับจำนวนครั้งที่ราคามาชน (touches) → ป้อนเข้าคะแนนด้วย

3. **fallback 3 ชั้น** พร้อมป้ายบอกความน่าเชื่อถือทุกชั้น:

   | ชั้น | เมื่อไหร่ | ป้าย |
   |---|---|---|
   | `pivot-cluster` | มีโซนที่ยืนยันแล้วเหนือราคา | **ยืนยัน · ชน N×** (เขียว) |
   | `lookback-high` | ไม่มีโซนยืนยัน ใช้จุดสูงสุดย้อนหลังแทน | **ไม่ยืนยัน** (เหลือง) |
   | `projected` | ราคาทะลุแนวต้านเดิมไปแล้ว ประมาณจาก ATR | **ประมาณ** (เหลือง) |

   สองชั้นล่างได้คะแนน "ระยะห่างจากแนวต้าน" แค่ 50 (กลางๆ) เพราะเราไม่รู้จริงว่ามีแรงขายรออยู่หรือไม่

4. **กันเป้าหมายตกใต้ราคาปัจจุบัน** — ระบบบังคับให้แนวต้านที่เลือกอยู่เหนือราคาอย่างน้อยเท่ากับระยะแจ้งเตือน
   ถ้าแนวต้านใกล้กว่านั้น จะขึ้น `auto (ใกล้แนวต้านเกินไป)` และ**ไม่ตั้งเป้ารอบนั้น** แทนการเตือนแบบไร้ความหมาย

### ⚠️ เรื่อง `× 0.999` ที่ต้องพูดตรงๆ

การเข้าต่ำกว่าแนวต้าน 0.1% คือการ **front-run breakout** — เป็นการเล่น scalp มาตรฐาน ได้ราคาดีกว่า
แต่มันคือการเข้า **ก่อน** ที่ราคาจะเบรกจริง ซึ่งจำนวนมากจะกลายเป็นการเด้งกลับ
→ ระบบจึงแสดงข้อความ **"เป็นการเข้าก่อนเบรก ต้องมีวอลุ่มยืนยัน"** คู่กันเสมอ
และปัจจัย RVOL ในคะแนนคือตัวที่แยกสองกรณีนี้ออกจากกัน

### เมื่อราคาแตะเป้าหมาย

1. แถวในตาราง**ไฮไลต์สีเหลือง + กระพริบ**
2. **เสียงเตือน** — บี๊บ 2 ครั้ง (880Hz → 1180Hz) ด้วย Web Audio API ไม่ต้องมีไฟล์ mp3
3. **Browser Notification** — ขอ permission ตอนเปิดหน้าเว็บครั้งแรก
4. เขียนลง **alert log** พร้อม timestamp (`data/alerts-history.json`)
5. ส่ง **LINE** ด้วย ถ้าเปิดใช้ในหน้า Settings

**กันเตือนซ้ำ:** เตือนแล้ว mark ว่า `triggered` ลง `data/alerts.json` → ไม่เตือนรัวทุกรอบ
มีปุ่ม **↺ reset** รายตัวในรายการเฝ้าดู และปุ่มรีเซ็ตทั้งหมด

> เสียงเตือนต้องมี "user gesture" ก่อนตามกฎของเบราว์เซอร์
> การกดปุ่ม Start หรือ Scan Now นับเป็น gesture แล้ว
> ถ้าไม่ได้ยินเสียง ให้กดปุ่ม **ทดสอบเสียง** ก่อนหนึ่งครั้ง

## 7. แหล่งข้อมูลหลายชั้น

ทำเป็น **adapter pattern** — แต่ละ provider เป็นไฟล์แยกใน `src/providers/`
เพิ่ม provider ใหม่ได้โดยสร้างไฟล์ที่ export object หน้าตาเดียวกัน แล้วเพิ่มชื่อใน `index.js`

### fallback แยกตาม "ชนิดข้อมูล" ไม่ใช่ตาม "provider"

นี่คือจุดสำคัญของการออกแบบ เพราะ Finnhub ฟรีให้ราคา realtime ได้ดีแต่**ไม่ให้แท่งเทียนเลย**
ถ้าเรียงลำดับแบบ provider เดียวรวบทุกอย่าง จะพังทันทีที่ขอแท่งเทียน

| ชนิดข้อมูล | ลำดับที่ใช้ |
|---|---|
| ราคาปัจจุบัน | Finnhub → Twelve Data → Yahoo |
| **แท่งเทียน** | **Yahoo → Twelve Data** (Finnhub ใช้ไม่ได้) |
| ปฏิทินงบ | Finnhub → Yahoo |
| ข่าว + sentiment | Alpha Vantage → Marketaux → Finnhub (เปลี่ยนลำดับได้ใน Settings) |
| float / short interest | FMP |
| screener | Yahoo |

### กลไกกันพัง

| กลไก | รายละเอียด |
|---|---|
| **Retry + exponential backoff** | รอ 2s → 6s → 18s **+ jitter ±25%** |
| **jitter สำคัญมาก** | ถ้าหุ้นหลายตัวโดน 429 พร้อมกันแล้ว retry พร้อมกันอีก ก็จะโดนซ้ำทั้งชุด การกระจายเวลาช่วยให้ทยอยผ่าน |
| **Rate limiter** | token bucket ต่อ provider ตามโควตาจริง (Finnhub 60/นาที, Twelve Data 8/นาที, Alpha Vantage 5/นาที) |
| **Cache** | ราคา 20s · แท่งเทียน 45s · แท่งรายวัน 12 ชม. · ข่าว 6 ชม. · ปฏิทินงบ 6 ชม. |
| **กันยิงซ้ำ** | คำขอเดียวกันที่วิ่งพร้อมกันจะรอผลของตัวแรก ไม่ยิงใหม่ |
| **โควตาหมด = ข้าม** | ไม่ยิงให้เสียเวลา round-trip |
| **403 = จำไว้** | endpoint ที่ไม่อยู่ใน free tier จะไม่ถูกเรียกซ้ำใน session นั้น (ไม่เผาโควตา) |
| **ไม่มี key = ข้าม** | ไม่ crash ระบบยังทำงานด้วย provider ที่เหลือ |
| **"ข้อมูลไม่อัปเดต"** | ขึ้นแบนเนอร์แดงด้านบน + ไฮไลต์แถวสีแดง + บอกเหตุผลเมื่อกางแถวดู |

## 8. หน้า Backtest

ย้อนดูว่าสัญญาณที่ระบบเคยให้ไว้ ถ้าเข้าตามนั้นจริงจะได้ผลยังไง
**เพื่อให้รู้ว่าเกณฑ์ที่ตั้งไว้ใช้ได้จริงหรือเปล่า ก่อนเอาเงินจริงลง**

สัญญาณทุกอันถูกบันทึกลง `data/signals-history.json` อัตโนมัติ (พร้อม breakdown คะแนนเต็ม)

### ตัวเลขที่คำนวณ

| ตัวเลข | ความหมาย |
|---|---|
| **Win rate** | ชนะกี่ % (คิดจากไม้ที่ตัดสินผลได้แล้วเท่านั้น) |
| **Avg gain / loss** | กำไร/ขาดทุนเฉลี่ยเป็นหน่วย R |
| **Expectancy** | ค่าคาดหวังต่อไม้ — **ตัวเลขสำคัญที่สุด** |
| **Max drawdown** | จุดที่ทุนสะสมลดจากยอดสูงสุดมากที่สุด (peak-to-trough ของ equity curve แบบ R) |
| **Profit factor** | กำไรรวม ÷ ขาดทุนรวม |
| **แยกตามช่วงคะแนน** | **คะแนนสูงได้ผลดีจริงหรือเปล่า?** ถ้าค่าคาดหวังไม่เพิ่มตามคะแนน แปลว่าระบบให้คะแนนยังไม่มีประโยชน์ |
| **แยกตามปัจจัย** | เทียบไม้ที่ปัจจัยนั้นคะแนนสูง (≥70) กับคะแนนต่ำ — ผลต่างเป็นบวกมาก = ปัจจัยนี้มีประโยชน์ ควรเพิ่มน้ำหนัก |
| **แยกตามวิธีหาแนวต้าน** | แนวต้านที่ยืนยันแล้วได้ผลดีกว่าค่าประมาณจริงไหม |
| **Equity curve** | กราฟ SVG ในหน้าเว็บ (ไม่ต้องโหลด library) |

### ข้อจำกัดของ backtest นี้ (แสดงในหน้าเว็บด้วย)

1. ใช้ข้อมูลระดับ**แท่งเทียน ไม่ใช่ tick** — ถ้าแท่งเดียวแตะทั้ง stop และเป้า จะนับเป็น**แพ้** (สมมติแบบระมัดระวัง)
2. **ไม่คิดค่าคอมมิชชั่น ค่าธรรมเนียม และ slippage** — ผลจริงจะแย่กว่าตัวเลขนี้
3. ไม่คิดกรณีไม่ได้ราคาที่ต้องการ (partial fill)
4. ไม้ที่ยังไม่แตะ stop/เป้าในกรอบเวลา คิดผลจากราคาปิดแท่งสุดท้าย (mark to market)
5. **ผลย้อนหลังไม่ใช่การรับประกันผลในอนาคต**

## 11. ข้อจำกัดที่ต้องรู้

### ยังไม่ได้ทดสอบกับข้อมูลจริง

โค้ดนี้ถูกพัฒนาและทดสอบใน **sandbox ที่บล็อกการเชื่อมต่อไปทุก host ของ provider การเงิน**
(`query1/query2.finance.yahoo.com`, `finnhub.io`, `api.twelvedata.com`, `www.alphavantage.co`,
`api.marketaux.com`, `financialmodelingprep.com` — ทั้งหมดถูกปฏิเสธที่ระดับ network egress policy)

**สิ่งที่ทดสอบแล้วครบ** (79/79 ข้อ ผ่าน ด้วยข้อมูลจำลอง):
server, REST API ทุก endpoint, ปุ่ม Start/Stop/Scan Now, การพิสูจน์ว่าไม่มี timer ค้าง,
watchlist CRUD + persist ลงไฟล์จริง, validate ticker, แจ้งเตือน + กันเตือนซ้ำ + reset,
คะแนน + breakdown, แนวต้าน, R:R, position size, settings + validation, provider interface,
backtest, error handling, หน้าเว็บทั้ง 3 หน้า

**สิ่งที่ยังไม่ได้ทดสอบ** — ต้องให้คุณลองบนเครื่องจริง:
- การดึงข้อมูลจริงจาก provider ทั้ง 6 เจ้า (โครงสร้าง response อาจไม่ตรงกับที่เขียนไว้)
- `run.bat` / `start.bat` บน Windows จริง (เขียนถูกต้องตามหลักแล้ว แต่ยังไม่ได้ดับเบิลคลิกจริง)
- เสียงเตือนและ Browser Notification ในเบราว์เซอร์จริง
- การส่ง LINE จริง
- ค่า default ของ `ATR_PCT_LOW/HIGH` และเส้นโค้งให้คะแนนทุกเส้น ยังไม่ได้ปรับเทียบกับหุ้นจริง

**แนะนำให้ทำตามลำดับนี้:**
1. `npm test` — ยืนยันว่าติดตั้งครบ (ควรได้ 79/79)
2. `npm run demo` — ดูหน้าเว็บ ลองปุ่ม ลองเสียง
3. `npm start` ตอนตลาดเปิด กับหุ้น 2-3 ตัว — ดูว่าดึงข้อมูลจริงได้ไหม
4. เก็บข้อมูล 1-2 สัปดาห์ แล้วดูหน้า `/backtest` ว่าเกณฑ์ใช้ได้จริงไหม **ก่อนใช้เงินจริง**

### ข้อจำกัดทางเทคนิคอื่นๆ

- **วันหยุดตลาดหุ้นเป็นค่าคงที่ในโค้ด** (`src/market-hours.js`) มีข้อมูลปี 2026-2027
  ต้องอัปเดตมือทุกปี · ไม่ครอบคลุมวันปิดครึ่งวัน (early close 13:00 ET)
  ถ้าไม่มีข้อมูลของปีนั้น ระบบถือว่าเป็นวันทำการปกติ
- **ไม่มีระบบล็อกอิน** — server เปิดที่ `localhost` ใครเข้าถึงเครื่องได้ก็เห็น API key ที่กรอกไว้
  อย่าเปิด port 3000 ออกอินเทอร์เน็ต
- **Twelve Data ตีความ timestamp เป็น UTC** ทั้งที่จริงเป็นเวลา exchange (ET)
  ทุกแท่งเลื่อนเท่ากันจึงไม่กระทบการเทียบ RVOL/VWAP ภายในชุดเดียวกัน
  แต่ถ้าสลับไปใช้ Twelve Data เป็นแหล่งแท่งเทียนหลัก การแบ่งวันของ VWAP อาจคลาดเคลื่อน
- **`positions.js` / `exitLoop` เดิมยังไม่ได้ต่อเข้ากับหน้าเว็บ** — ดูหัวข้อถัดไป

### สิ่งที่ตกลงกันไว้แต่ยังไม่เสร็จ

ตอนวางแผนตกลงว่าจะ "เก็บ `positions.js` + ทำ UI ตารางไม้ที่เปิดอยู่"
**ส่วนนี้ยังไม่ได้ทำ** — โค้ด `positions.js` และ `exitLoop` เดิมยังอยู่ครบและใช้ได้ในโหมด CLI (`npm run cli`)
แต่หน้าเว็บยังไม่มีตาราง "ไม้ที่เปิดอยู่" และไม่มีสัญญาณออก 7 แบบ
(STOP / TP1 / TP2 / BREAKEVEN / EMA5_LOST / VWAP_LOST / TIME_STOP)

ดูรายละเอียดครบทุกข้อใน **`CHECKLIST.md`**

## คำเตือนความเสี่ยง

เครื่องมือนี้เป็น **เครื่องมือช่วยคัดกรองหุ้น (screening tool)** เท่านั้น **ไม่ใช่คำแนะนำการลงทุน**
และไม่ใช่การรับประกันผลตอบแทนใดๆ

- คะแนนและ "Expected Move" คำนวณจากค่าสถิติย้อนหลัง (ATR) ซึ่ง **ไม่ได้บอกอนาคต**
  ราคาอาจเคลื่อนไหวมากหรือน้อยกว่านั้น หรือไปคนละทางก็ได้
- ราคาเป้าหมายที่คำนวณจากแนวต้าน −0.1% คือการ **เข้าก่อนที่ราคาจะเบรกจริง**
  ซึ่งจำนวนมากจะกลายเป็นการเด้งกลับ ต้องมีวอลุ่มยืนยันประกอบ
- ข้อมูลมาจาก API ฟรี อาจล่าช้า ไม่ครบ หรือผิดพลาดได้ **ควรตรวจสอบกับโบรกเกอร์ก่อนตัดสินใจทุกครั้ง**
- ผลการทดสอบย้อนหลัง (backtest) ไม่คิดค่าคอมมิชชั่นและ slippage ผลจริงจะแย่กว่าที่เห็น
- การซื้อขายหุ้นระยะสั้นมีความเสี่ยงสูงที่จะสูญเสียเงินต้น **ผู้ใช้รับความเสี่ยงเองทั้งหมด**
